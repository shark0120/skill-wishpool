# Repo ↔ Server Drift Audit

## 為什麼需要

非 git 管理的專案（直接 scp/sftp 上線的 PHP 站最常見）很容易出現：
本機是幾個月前的快照，線上被人手改過而且更新。這時候**用本機檔案部署 = 靜默刪掉線上較新的程式**，
而且不會有任何錯誤訊息，通常幾天後才會被使用者發現「某個功能不見了」。

真實案例：某站 167 個檔中有 14 個線上較新，其中 `user/kyc.php` 線上 15486 bytes、本地只有 10441 bytes，
另有 1 個檔案只存在線上。若當時直接全量部署，會一次抹掉四千多行手改成果。

## 觸發

- 「本地跟線上一樣嗎」「有沒有差異」「drift」
- 「部署會不會蓋掉東西」「線上是不是比較新」
- 接手任何**非 git**、靠 scp/sftp 上線的專案
- 準備做第一次全量或大範圍部署之前（**必跑**）

## 禁止

- **本 skill 唯讀，絕不寫入伺服器。** 只允許「線上 → 本地」單向拉取。
- 不自動同步含憑證的檔案（`config/database.php`、`.env`、任何 `*secret*`／`*credential*`）——列出來讓人工判斷。
- 不把主機位址、帳號、密碼寫進本 skill 或任何狀態檔；憑證一律從該專案既有的部署腳本或使用者當下提供取得。
- 不因為「線上比較新」就假設線上是對的：先看內容，可能是別人改壞的。

## 步驟

1. **決定掃描範圍**：程式碼與樣板目錄（例：`app/`、`config/`、`resources/views/`、`public/`），
   副檔名限 `.php .js .css .html` 等文字檔，排除 `*.bak*`、`*.log`、壓縮檔、`node_modules`、`vendor`。

2. **兩邊各算 md5**
   - 線上：`find <遠端目錄...> -type f \( -name '*.php' -o -name '*.js' \) ! -name '*.bak*' -exec md5sum {} \;`
   - 本地：逐檔 `hashlib.md5(path.read_bytes()).hexdigest()`
   - 用「相對專案根目錄的路徑」當 key 對齊兩邊。

3. **分四類輸出**
   | 類別 | 意義 | 風險 |
   |---|---|---|
   | 相同 | 一致 | 無 |
   | 內容不同 | 兩邊都有但不一樣 | **高**：部署會覆蓋 |
   | 只有本地有 | 尚未部署 | 中：可能是新功能 |
   | 只有線上有 | 本地缺 | **高**：容易被誤刪或漏帶 |

4. **對「內容不同」補證據**：兩邊 bytes 與線上 mtime。
   線上較大／較新 ⇒ 極可能是本地過期，先別部署。

5. **提報給使用者，等指示**。要同步時才做下一步。

6. **同步（僅線上 → 本地）**
   - 先把本地版本備份到 `<專案>/.local-backup/<timestamp>/<原路徑>`
   - `sftp.get()` 拉下線上版本
   - 拉完立刻重算 md5 與線上比對，確認一致
   - 跳過憑證類檔案並在報告中明說跳過了哪些

## 驗收

- 輸出四類數字，且「內容不同」每一筆都有 本地 bytes / 線上 bytes+mtime
- 同步後重跑本 skill，「內容不同」歸零（憑證類除外）
- 全程伺服器端沒有任何寫入（只有 `find` / `md5sum` / `stat` 這類唯讀指令）
- 本地備份目錄確實存在且檔案數與同步數相符
