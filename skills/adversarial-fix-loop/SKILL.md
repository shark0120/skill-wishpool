# adversarial-fix-loop

## 為什麼單向稽核不夠

一般流程是:稽核員找問題 → 修復者修 → 上線。這個流程有兩個致命盲點:

**盲點一:修復者相信稽核員的分析。**
稽核員說「未加引號的 heredoc 讓值在寫入時執行」。修復者加了引號、宣稱修好。
但實際上 `${VAR}` 是參數展開,POSIX **不會**重新掃描展開結果找命令替換 ——
真正的 RCE 來自稍後 `source` 那個檔案,**每次啟動執行一次**。
加引號修好了「不存在的問題」,真漏洞完好無損,而且現在有一個「已修復」的 commit 背書。

**盲點二:修復者自己也會錯,而且會不自覺地掩蓋。**
把「四個環境變數」改成「七個」(實際十一個),並附上行號引用 —— 而那個引用範圍
**剛好就是排除掉另外四個的窗口**。不是故意的,但外觀上與刻意挑選無法區分。

兩個盲點的共同點:**修復者是最沒資格驗證自己修復的人。**

## 鐵律

1. **修的人與驗的人不同**,且驗的人**不看修復說明**,只看程式碼與實際行為。
2. **驗的人有義務挑戰稽核員的分析**,不只確認修好沒。機制錯了,修法一定錯。
3. **修復者有義務反駁稽核員**。發現稽核員的機制描述有誤,要明說並附證據。
4. **一律用跑的驗,不用讀的驗。**
5. **重新植入缺陷**:把 bug 放回去,確認測試會紅且訊息指得出真正失敗模式。
6. **改完必重驗**,包括先前已通過的項目(尤其雜湊、產生的檔案、快照)。

## 迴圈

```
FIND (稽核員 A) → 缺陷清單 + 機制假設
   ↓
FIX (修復者 B) → 實際重現 → 挑戰或修正機制假設 → 修 → 自測 → 附證據
   ↓
VERIFY (稽核員 C,非 A 非 B) → 不看修復說明 → 獨立重現 → 找新缺陷
   ↓
critical/high 為 0 ?  否 → 回 FIX(換人)   是 → SHIP
```

**C 不能是 A。** A 已經對機制有既定看法,會傾向確認自己的假設。

## 修復者的責任(B)

- **先重現,再修。** 修一個你沒親眼看過的缺陷,等於猜。
- **確認機制。** 稽核員給的是假設。用最小實驗驗證:
  ```
  原始碼 + payload → 觀察實際發生什麼(檔案內容?何時執行?哪個進程?)
  ```
- **機制不同就明說。** 「稽核員說 X,實測是 Y,證據如下」。這是最有價值的產出。
- **找稽核員漏掉的層。** 修了輸入驗證,那**輸出端**呢?裝完之後有人改了設定檔呢?
  單層防護通常不夠。
- **不要只修被點名的那一處。** 搜尋同類型的所有位置。

## 驗證者的責任(C)

- **不讀修復說明**,直接讀程式碼與跑實驗。「已修復」四個字沒有證據價值。
- **重現原始攻擊**,確認現在會被擋 —— 而且是**明確拒絕**(非零退出 + 可讀訊息),
  不是靜默接受。
- **找修復引入的新缺陷。** 修復本身也是改動,也會有 bug。
- **驗證修復的完整性**:同類型還有沒有別處?防護有幾層?繞得過嗎?
- **檢查衍生產物**:改了檔案 → 雜湊還對嗎?產生的設定還合法嗎?文件還準嗎?

## 每個缺陷的最小證據包

```
缺陷:      <一句話>
機制:      <實測確認的,不是假設的>
重現:      <確切指令 + 觀察到的結果>
修法:      <改了什麼,為什麼這樣改能斷開機制>
修後重現:  <同一指令 + 現在的結果>
反向驗證:  <把缺陷放回去 → 測試紅了嗎?訊息對嗎?>
副作用:    <雜湊/產生檔/文件 有沒有因此失效>
```

沒有「修後重現」和「反向驗證」的修復,不算修完。

## 常見的假修復

| 假修復 | 為什麼假 |
|---|---|
| 加了引號但值仍被 `source` | 斷錯環節,執行點在別處 |
| 修了輸入驗證但沒管事後竄改 | 只有一層;裝完後可改的檔案仍是入口 |
| 訊息消毒了但訊息根本顯示不出來 | 修了下游,上游已經把它吃掉 |
| 測試綠了但沒反向驗證 | 斷言可能永遠為真 |
| 改了程式沒重算雜湊 | 發佈的驗證從此永遠失敗 |
| 只修了稽核員點名的那一個檔 | 同樣的模式散落在其他檔案 |

## 何時停

**四個面向都 `publishable: true` 才停**,而不是「這輪沒發現新問題」。
沒發現可能是沒找對地方 —— 前幾輪都有發現的話,這輪突然乾淨要更警覺。

時程壓力是最常見的失守原因。**趕時間不是降低門檻的理由,是延後上線的理由。**

## 安全界

- 驗證者**唯讀**,不修東西。
- 重現攻擊在**隔離的暫存目錄**做(`HOME=/tmp/xxx`),不要在真實家目錄跑 payload。
- 用無害的 marker(`touch /tmp/pwned`)證明執行,**不要**用真的破壞性 payload。
- 不因為「已經修三輪了」就放行。輪數不是證據。
